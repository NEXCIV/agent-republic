## 2. 结果

### 2.1 帧率与绘制

| 指标 | 桌面 | 移动模拟 |
|---|---:|---:|
| 帧率中位数（headless，未锁帧） | 170 FPS | 170 FPS |
| 等效帧时间 | ≈ 5.9 ms | ≈ 5.9 ms |
| Draw calls / frame | 78 | 83 |
| Triangles / frame | 9,372 | 9,452 |
| Geometries | 95 | 95 |
| Textures | 3 | 3 |
| Shader programs | 9 | 9 |

说明：

- Headless Chrome 的 rAF 未锁 60Hz，170 FPS 只说明**在该软件渲染环境下帧预算充足**，不能外推为真机帧率。
- 桌面需求循环为 `demand`：相机/角色静止时不再请求新帧，因此空闲时不会持续占用 GPU。
- 移动模拟命中 low quality tier：内部 DPR 1、关闭 antialias；表格中的 170 FPS 仍是软件渲染结果。

## 3. 降级策略（已实现）

1. **无 WebGL / 上下文丢失**：`detectWebGl` + ErrorBoundary + `webglcontextlost` → 静态 SVG 平面图 + 等价 HTML 建筑目录，交易与项目页不受影响。
2. **质量档位**（`quality.ts`）：
   - coarse pointer、`prefers-reduced-motion`、≤4 逻辑核心或 ≤4GB `deviceMemory` → `low`；
   - `low`：DPR 1、关闭 antialias；`high`：DPR ≤2、antialias 开启。
3. **运行时自动降级**：连续 120 个主动渲染帧平均低于 24 FPS 时，单次降为 `low`（只降不使用静态图）。
4. **空闲与离屏**：静止时 `demand` 循环停止；IntersectionObserver 离屏时 `frameloop='never'`；页面隐藏时暂停 frame 轮询。
5. **减弱动态**：`prefers-reduced-motion` 下不播放里程碑脉冲，Agent 位置直接采用最新 frame，不插值。
6. **无阴影贴图 / 无 Bloom**：仅一个共享径向渐变纹理作 contact shadow，5 个 draw call；单一 PMREM 环境光。
7. **Agent 合批**：30 个角色使用 InstancedMesh（机体、地面环、拾取球各一个），不按角色增加 draw call。

## 4. 未验证 / 风险

- **未在真实 GPU 或真实手机上测量**：目标 50–60 FPS（桌面）与 24–30 FPS（移动）仍需在目标设备上手测；本报告不宣称达成。
- 未测量长期运行温度、耗电、内存增长或多标签页竞争。
- 当前没有 GLB/纹理资产；E6-02/E6-03 的程序化几何不代表后续美术资产的体积与 draw calls。
- 自动降级只降低 DPR，不会自动切换为静态图；极低端设备仍可能动画卡顿。
- 视觉回归与截图基线属 E6-08。
