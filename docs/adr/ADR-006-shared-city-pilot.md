# ADR-006：共享城市生活 — 受限移动试点

- 日期：2026-11-27
- 范围：E3-05，生活模拟阶段 0 及阶段 1 的首个可验证切片
- 状态：本轮隔离试验的开发约束；不代表其已实现、已通过验收或获准对公网开放

## 背景与取舍

现有本机咖啡街、桌面游客试玩均按浏览器会话隔离。其移动、任务和记录可重放，但两个浏览器不属于同一个城市。把游客存档直接改成同一份，会让不同访客能操纵同一个角色，不能证明居民归属、动作授权或共享活动的一致性。

先在独立试验环境建立一个共享的链下生活**动作与回执服务**，只验证两名已分配测试居民的固定点位移动。保留现有游客试玩和本机 MCP，不使用其 cookie 或数据库记录作为共享居民的所有权证明。

这不是第二套正式世界引擎。本轮仅记录隔离的生活活动；`packages/domain/src/world-v1.ts` 仍是唯一 `WorldFrameV1`、`AgentObservationV1` 定义。正式场景 `district-01@1`、60 秒模拟 tick、事件来源、合约参数及 `WorldFrameV1.facts` 均不修改。活动日志中的命令时刻和路线只是 DEMO 行为证据，不是链上事实。试点复用 300 米预览场景的已测绘步道路网，只开放 `cafe`、`plaza`、`governance`、`works` 四个固定地点，而非任意坐标。未来接入正式世界前，另立场景及投影 ADR，若需要版本/schema 演进，则同步规格与测试向量。不得将测试居民写入正式公民列表、增加任何真实公民人数或令链上项目阶段发生变化。

## A. 账号、居民和授权边界

1. 正式账号沿用已有站内 `app_user`、认证会话及既有的 owner 绑定机制，不新建平行的登录/链上身份体系。首轮共享生活预设邀请制、一账号一链下居民；认领本身不产生正式公民权利，不等价于 `CitizenRegistered`。实际生产登录方式、认领流程和首次开放条件须在接入实现前经确认及实测，目前尚未确定。
2. 隔离试点只预分配 `01` 和 `02` 两名测试居民，由内部操作者为单一居民发放、轮换、撤销不透明的限时应用凭据；持久层保存凭据哈希，不保存其明文。试验凭据默认有效 1 小时，最长 24 小时，仅适用于内部测试，未来正式授权期限需独立评审。操作服务从有效凭据查得可信测试主体，固定授权范围仅为 `observe`（观察同城可见的移动状态）、`moveTo`（移动该居民）和 `receipt`（读取该居民自己的回执）；不开放凭据发放、轮换和撤销给 Agent。调用参数、钱包地址字符串、浏览器游客 ID、模型自述均不能改变该主体，不能冒领其他居民。测试凭据不是生产用户登录凭据，不得在正式路由直接接受。
3. 后续 HTTP 和 MCP 的授权适配层必须从有效的凭据及持久归属记录确定主体；按独立作用域限制观察、提交动作和读取自己的回执。发放、暂停、撤销、过期及被移除的归属要成为明确的服务端状态；本轮内部操作者的凭据接口不替代正式用户授权流程。应用连接凭据不等于 Agentic Wallet、签名授权或链上 Delegate；客户端持有的模型供应商密钥始终由自身 Harness 管理。
4. 在正式开放前，验证同一动作经 HTTP/MCP 得到一致的权限校验、语义及回执。在未完成目标 Harness 的真实协议和授权验收前，不开放远程 MCP 或浏览器共享认领。本轮不建立匿名共享写接口，不接管钱包，不部署到公网。

## B. 最小动作契约与权威执行

`moveTo` 动作使用严格输入 `{ action: 'moveTo', requestId: uuidV4, destination: { place } }`，`place` 仅允许四个固定地点的 ID，幂等 UUID 统一转为小写。服务端根据凭据确定居民 ID，从自身状态确定出发点、路线、速度及到达时刻；不得从请求接受任意坐标、被操作的居民 ID、时钟、到达证明、链上写入、自由文本或未经审核的公共事件。

一期只支持前往固定点位。新测试存档内 `01` 从中央广场 `plaza` 出发、`02` 从咖啡摊 `cafe` 出发，使用同一个服务端路线版本及 4 米/秒的演示移动速度。服务端入参校验、权限、位置/忙碌状态检查、动作受理及唯一回执属于同一应用服务；HTTP、MCP、客户端动画将只做适配与呈现。隔离试点采用专用 SQLite 存储居民、凭据和动作记录，复用支持 `node:sqlite` 的运行条件，不读取或复用浏览器游客/本机试玩数据库。在动作受理和凭据生命周期操作中保持原子边界；未来生产存储另行迁移和验证。

| 项目 | 规则 |
| --- | --- |
| 动作受理 | 有效居民在当前可行动状态下可前往白名单位置；未知点位、错误主体、超出固定授权范围、无效/过期/已撤销授权，以及已有未完成移动都不能产生新动作 |
| 幂等键 | 以居民与请求 ID 划定范围；完全相同的动作重放返回同一行动回执的当前状态，不重复移动；同一居民的相同请求 ID 若内容不同则冲突；不同居民的请求命名空间互不占用 |
| 回执 | 明确区分受理与完成：受理不等于到达，完成依据服务端已记录的开始和到期时刻；错误原因可机器识别，但不披露其他居民的私有数据 |
| 时间 | 注入或由服务端读取可信时间；移动耗时按路线长度和演示速度计算并向上取整到毫秒，对同一已受理的记录，按同样的时间输入能重现移动状态。到期前未到达，到期时/之后由下一次获授权的事务补算到达，记录原定到达时刻；重复观察不得重复生成完成事实 |
| 同时活动 | 第一版每个居民仅有一个尚未完成的移动，不锁住其他居民；两名居民可在同一共享试点独立选择路线，随后同时出现在相同目的地 |
| 公开/私有 | 试点共同可见的信息只包含测试居民 ID、位置、可观察的路线及其服务端时间/事件来源，标注 `AI SIMULATED · DEMO`。共享投影至多返回最近 40 条移动开始/到达事件，只向已授权试点主体可见；主体归属、访问凭据、请求与私有回执细节不得进入共同投影或其他居民的私有读取结果 |

隔离试验设置每位测试居民最多 300 条已受理移动动作记录的容量限制，重放已有动作仍按幂等规则读取现有回执；此上限是资源和试验的边界，不是生产可承载人数、吞吐量或反机器人能力的保证。

不能用“AI 说它到了”、客户端动画播放到结尾、浏览器按键或钱包状态代替动作结果。已受理动作的时间推进不需要触发模型调用。凭据撤销或轮换不撤销已受理的确定性移动；移动可以按既有记录结束，不能静默改写历史。用户级暂停流程在正式授权阶段实施。

## C. 分阶段交付与验收清单

当前切片只建立领域契约、凭据受限的隔离共享移动服务与可复现测试。无需先开放真实账号认领，亦无需为了测试引入公网接口或新场景资产。以下为验收目标，实际运行结果另行记录：

| 用例 | 通过条件 |
| --- | --- |
| 同城可见 | 测试居民 A 发起移动；测试居民 B 仍有独立动作权，但从共同读取结果可观察到 A 在前往固定地点及到达后的状态；B 的位置和记录不会被 A 改写 |
| 正确归属 | 不可信调用参数不能指定或操纵另一个居民；读取自己回执时必须匹配授权主体；共同可见结果不含私有凭据或私人请求数据 |
| 可重试 | 重试相同请求返回原回执；同 ID 改目的地被拒绝；两名居民可独立使用同名幂等 ID；重复动作和到期重算无重复结果 |
| 规则限制 | 错误动作、未知地点、超出固定授权范围或越权、无效/过期/轮换/撤销凭据、移动中重复新动作被明确拒绝，不产生新的移动记录 |
| 时间边界 | 注入可控制时钟验证受理后立即、到期之前、恰好到期、之后和重复观察；路线起终点与可见状态一致 |
| 持久恢复 | 关闭测试数据库连接并重新打开，核对已保存行程、动作回执、时间推进及凭据有效状态；整个测试使用独立数据库 |
| 隔离 | 无链上/钱包写入、无模型调用、不影响本机咖啡街存档或独立游客；不创建并行的正式 WorldFrame，不新增主网数据或冒充链上确认 |

## F. 咖啡街会面闭环（E3-05）

同一隔离 SQLite 试验库增加独立生活会面记录（从 v1 以事务性加表方式迁移，不替换既有移动数据）。规则 Agent 可邀请另一位测试居民在咖啡街会面；邀请、接受/婉拒、发言都由各自的既有试点凭据确定主体。请求仅可包含固定动作、受邀方/会面 ID、白名单回应/台词键和幂等 UUID；不接受自由文本、伪造说话者、坐标或完成结果。同一请求重放不产生重复事件，相同 ID 改内容拒绝。邀请有到期时间，已接受会面有旅行期限，交流有轮次期限。每轮仅允许指定说话者在服务端允许时间发言。

双方接受后仍各自提交移动请求；咖啡街会面使用柜台至长椅前步道的两个不同站位。只有两人均实际到达各自站位才开始交流，不能用动画、到达自述或页面操作替代。会面中不允许其他目的地的移动。四轮固定白名单台词分别由受限规则客户端提交，公开内容只引用已发生的会面或未来意愿，不冒充链上事项。最后一轮结束并经过停留时间后记录完成事件，两人的私有记忆和各自对对方的累计会面次数在同一事务写入；拒绝或过期不增加关系记录，重试/重启不重复计算。只有共同会面状态、公开对话和已完成次数可在本机只读网页展示，个人记忆内容和请求键不进入共同投影。

本切片验证初次邀请、拒绝、接受、行走会合、轮流发言、完成与记忆、超时、重启恢复、主体与幂等边界。沿用现有 3D 人物、咖啡街路网和 `DEMO / AI_SIMULATED` 标记；面向真实外部 Harness 的登录、授权、自由文本审核与正式 WorldFrame 投影仍未开放。正式链上身份、经济与 60s tick 不改变。

## G. 从会面约定到公共建设中心共同调研（E3-05）

完成咖啡街四轮对话后，已核验的会面 ID 可作为共同调研的来源；每个会面只允许创建一次调研邀请。两名规则主体分别发起、接受/拒绝、移动、开始观察、提交记录。继续依赖既有短期凭据、严格动作 schema 和每居民幂等请求键；不接受调用者自填调研结果、坐标、时长、报告作者或完成状态。建设中心调研复用 `works.patrol` 已测绘的入口外侧步道（01：X=95，Z=67.346）与施工区人行通道（02：X=95，Z=60.55），高度由现有导航路网计算。两人独立赴约到不同地点；只有两人都在站位并且没有未完行程才进入观察。每人至少观察 8 秒，在原站位提交自己分配的检查项，服务器生成位置、时间和受控场景观察文本。两份记录齐备时同一事务生成唯一共同报告和完成事件，单份不算任务完成。

SQLite 试验库 v3 只新增调研表，保留既有移动与会面记录。任务邀请、赴约、观察各有期限，超时或拒绝不生成完成报告；重启、重复提交、跨主体和无到场证据重试不增加计数。运行器优先履行上一轮会面约定；网页显示双方任务、调研站点、实际记录、完成回执和同框镜头。只记录 NEXCIV 虚拟场景的规则观察，不冒充现实安全检测、链上贡献或 BUILD/REP；正式身份、外部 LLM/MCP、经济与 `WorldFrameV1` 不变。

## H. 02 号本机 MCP 试验（E3-05）

在本机启动器和 `scripts/nexciv-shared-mcp.mjs` 的进程环境中提供相同的 `NEXCIV_SHARED_AGENT_KEY`。该值由操作者用 32 个随机字节生成并编码为 base64url。启用后，原控制器继续驱动 01，02 的决策由持有该凭据的本机 MCP 客户端提交。`observe_shared_city` 返回试点共同行程、会面、调研及 02 自己的记忆。`act_in_shared_city` 走相同的移动、社交与调研规则。授权主体由服务端固定为 02，网页只消费公开投影，并显示该 MCP 最近是否调用过试点服务。

解除试验时使用默认配置重启本机进程。既有移动、会面和报告随同一 SQLite 存档恢复。正式账号绑定与受邀用户接入继续按 §A 验收。

## I. 双居民的 MCP 与 HTTP 接入（E3-05）

共享试验启动前，在服务端进程设置 `NEXCIV_SHARED_AGENT_01_KEY` 和 `NEXCIV_SHARED_AGENT_02_KEY`。分别用 32 个随机字节生成 base64url 字符串，两个值必须不同。可以仅设置一个，另一位居民由规则 Agent 驱动。旧配置 `NEXCIV_SHARED_AGENT_KEY` 仍可作为 02 号的服务端后备值。配置完成后运行 `node scripts/start-nexciv-shared.mjs`，在浏览器打开本机 [共享城市](http://127.0.0.1:3142/nexciv-preview/shared)。

Windows PowerShell 可在当前终端生成凭据并启动服务。

```powershell
$env:NEXCIV_SHARED_AGENT_01_KEY = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
$env:NEXCIV_SHARED_AGENT_02_KEY = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
node scripts/start-nexciv-shared.mjs
```

| 客户端 | 本机接法 |
| --- | --- |
| MCP | 以 stdio 启动 `node scripts/nexciv-shared-mcp.mjs`，在该客户端进程设置 `NEXCIV_SHARED_AGENT_KEY` 为其居民的凭据。调用 `observe_shared_city` 和 `act_in_shared_city`。 |
| HTTP | 向 `POST http://127.0.0.1:3142/api/nexciv-preview/shared` 发送 JSON 和 `Authorization: Bearer <该居民的凭据>`。先发送 `{"action":"observe"}`，返回的 `viewerResidentId` 是已授权居民。移动请求包含 `action: "moveTo"`、UUID v4 `requestId` 和 `destination: { "place": "works" }`。 |

服务端从凭据判定居民。社会动作可以包含对方作为邀请目标，每个居民只提交自己的移动、会面回应和调研结果。观察只提供本人的私人记忆。凭据错误、重复配置、浏览器写入和请求自报居民身份会被拒绝。两个入口使用同一份 SQLite 存档和同一套动作校验。网页显示接入状态、公开行程和共同报告。用户自己的模型 API Key 保存在所用客户端内。

更换或清除服务端环境中的凭据后重启试验进程，旧凭据随之失效。已接受的活动和共同报告继续从同一个存档读取。该试验仅监听回环地址，正式账号授权及远程 MCP 仍按 §A 验收。

## J. 网页创建角色与接入（E3-05）

本机操作员可以为 01、02 各配置一个一次性试玩邀请。邀请由本机组织者通过私下渠道分别交给参与者。每个居民用邀请方式或 §I 的固定凭据方式之一。推荐用专用新存档试验。

```powershell
$env:NEXCIV_SHARED_PILOT_DB = Join-Path (Get-Location) 'cache/nexciv-invite-pilot.sqlite'
$env:NEXCIV_SHARED_INVITE_01 = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
$env:NEXCIV_SHARED_INVITE_02 = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
node scripts/start-nexciv-shared.mjs
```

进入 [本机入城页](http://127.0.0.1:3142/nexciv-preview/shared/join)。在两个独立的浏览器会话分别使用两份邀请，填角色名，从现有两套绑定模型选一套外观。创建成功后，打开同页的 MCP 或 HTTP 配置并生成接入凭据。共享页面实时读取名字、外观和 Agent 活动。现有的固定凭据模式按 §I 启动。

一份邀请只创建一个测试席位。浏览器管理会话有效期为七天。席位保留在该试验存档，失去浏览器会话后当前版本需要由组织者新建试验存档来开展下一轮。接入凭据最长有效一天，发放时显示一次。重新生成或撤销立即取消旧凭据，已受理的活动继续由城市服务推进。数据库保存凭据、浏览器会话和已使用邀请的哈希。API 通过凭据确定归属，公开投影只含角色名和外观等共同可见信息。每个玩家自己的模型 Key 留在 MCP 客户端或本地 Agent 程序。

该页面是隔离本机 DEMO，支持两个既有席位。正式登录、跨设备账号恢复、对外授权和 Agent ID 绑定仍按 §A 验收。
