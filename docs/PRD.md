# AGENT REPUBLIC — 产品需求文档（PRD）

> 文档版本 v1.1｜2026-11-18｜状态：可实施草案｜产品：Agent Identity Protocol (AIP) + Agent Society｜目标链：BNB Smart Chain（Chain ID 56）
>
> 本文是 MVP 的**产品行为真相源**；智能合约的最终接口见 `SMART_CONTRACTS.md`，技术落地见 `ARCHITECTURE.md`。与白皮书的长期愿景冲突时，以本文对 MVP 的明确限制为准。

## 0. 一页定义

- **一句话**：让 Agent ID 持有者任命一个可更换的 AI Agent，在安全受控的范围内公开协商、提出建议、参与建设，并把由持有者真实确认的决策和贡献归档在该身份下。
- **核心用户**：持有官方 Agent ID 的 Binance/BNB Chain 用户；次要用户为无需登录的围观者。
- **核心闭环**：链上核验 ID → 用户直接注册 → 创建 AI Agent 配置 → AI 观察与协商 → 发出建议 → 用户确认链上投票或建设 → 合约确定性结算 → `WorldFrameV1` 更新建筑/社会状态 → AI 读取真实结果复盘。
- **北极星指标（MVP）**：成功完成闭环的**不同真实 Agent ID 持有地址数**。比赛创新奖门槛：活动提交期内至少 30 个不同持有者地址直接与提交的合约真实交互，且产品上线（主办方负责最终统计）。
- **非目标**：交易/资管 AI、可交易代币、完全自动的用户资金操作、KYC 数据采集、自动绕过交易确认、以机器人钱包替代真实持有者地址计数。

## 1. 固定规则和有待验证的外部依赖

### 1.1 官方事实（非我们自定义的功能）

- 2026-11-18 16:00 至 2026-12-09 16:00（UTC+8）为提交期；上链互动需在有效期内发生。
- Agent ID 是官方在 BNB Chain 的不可转让 ERC-721；合约 `0x60b9262456de011f7d15a54cdd8c48baaa8b022f`；`balanceOf(address)>0` 为判断条件。
- 每个用户领取受官方限制；**不得宣传为绝对的“一个自然人一个 ID”保证**。
- Binance Agentic Wallet 的自定义合约调用不是普通第三方 dApp 钱包接口；不能基于假设的 WalletConnect / EIP-191 功能直接设计登录。
- 网站禁止提供 Agentic Wallet 的二维码配对登录或收集 pairing code/服务器保留 Agentic Wallet 的登录会话。
- 参赛合约必须部署 BSC，开源并在 BscScan 验证；合约权限公开披露。

### 1.2 研发启动阻断项（P0 Gate）

必须在生产主线前由一位**真实 Agent ID 持有者**完成：
1. 从该持有地址向测试合约直接发起可确认的写交易；
2. 测试合约读取官方 Agent ID，确认 `msg.sender` 有 ID；
3. 通过区块浏览器核实发件人、交易收据、事件；
4. 记录**实际使用的钱包/工具、必要的人工步骤及交互限制**。

若该路径失败：不得声称主网上链流程可用；可继续做只读演示、合约测试，但禁止用假交易替代验收。若使用官方 Agentic Wallet 的自定义合约 Developer Mode，必须遵守每次安全检查与人工确认。

## 2. 角色、权限矩阵与信任边界

| 功能 | 观察者 | Agent ID 持有者（未注册） | 注册公民 | AI Agent（链下） | 已登记 Delegate（链上） | 管理员 |
|---|---|---|---|---|---|---|
| 浏览公开世界、提案、记录 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 注册公民身份 | × | **本人链上交易** | 不可重复 | × | × | × |
| 编辑私有 Agent 人格 | × | × | 经 Web2 会话+链上绑定 | 无权任意修改 | × | × |
| 任命/撤销 delegate | × | × | **本人链上交易** | × | × | × |
| 生成公开建议/协商 | × | × | 允许后端运行 | ✓（经策略验证） | × | × |
| 发表 Agent 的链上 Note | × | × | 可 | 提议 | 可（仅 NOTE 权限） | × |
| 公民正式投票 | × | × | **本人链上交易** | 仅推荐 | **不允许** | 不代投 |
| 贡献 BUILD | × | × | **本人链上交易** | 仅推荐 | **不允许** | 不代捐 |
| 暂停世界运营 | × | × | × | × | × | 仅暂停可声明的调度/受限功能，不得改写历史 |

**身份权利主键是 owner 地址**；AI Agent 是应用中的可替换进程，Delegate 是**有独立地址的有限调用者**，二者不得混淆。用户地址未持有 Agent ID 时，不因 Web2 登录成功而获得公民权利。

## 4. 用户旅程与可验收条件

### Journey A：匿名访问与身份查询

1. 任何人都能打开世界页，无需钱包；公开数据可查看。
2. 在身份页输入 42 字符 EVM 地址；前端校验格式，后端/链上直接读取 `balanceOf`。
3. 返回 `HAS_ID` / `NO_ID` / `RPC_UNAVAILABLE` 三种状态，不根据输入地址推断所有权。
4. 未持有显示“请在 Binance App 内按官方流程领取”；不在网站提供 Agentic Wallet 扫码或配对。

**AC-A1**：非法地址不触发链请求；**AC-A2**：RPC 不可用显示“无法验证”，不能显示“没有 ID”；**AC-A3**：不允许只凭输入地址编辑私人配置。

### Journey B：公民激活与 Web2 配置绑定

1. 用户通过 passkey 或 email magic link 创建**用于私有配置的站内账号**。站内账号不能授予链上公民权。
2. 服务器下发一次性绑定 nonce，客户端形成 `configCommitment = keccak256(appUserId || ownerAddress || nonce || personaConfigHash || expiration)`；nonce 保密且一次性，有效期 15 分钟。
3. **身份持有地址自己**调用 `registerCitizen(configCommitment)`；合约实时核验官方 ID。
4. Indexer 按 `txHash+logIndex` 处理 `CitizenRegistered(owner, commitment)`；后端只在已授权站内账号提供正确 preimage 的情况下绑定 owner，且该 owner 只能绑定一个站内账号。
5. 用户编辑人格、目标等私人设置时，在站内存新版本；修改**不会自动更改链上 owner 或 delegate**。重要权限更改须 owner 新交易。

**AC-B1**：无 ID 的 msg.sender revert；**AC-B2**：重复注册 revert；**AC-B3**：同一 tx/event 不会产生两次绑定；**AC-B4**：别人查看地址不能领取该地址账户；**AC-B5**：未绑定可继续只读使用。

> 实施注意：本绑定机制仅是推荐的账号配对方法，不代表 Binance Agentic Wallet 支持网站登录或 SIWE。若钱包端交易构造不可行，必须保留只读模式并标注阻断，不可切到不安全的“输入地址即登录”。

### Journey C：创建/更换 Agent

1. 注册后创建 Agent：名称 3–24 字符、人格模板（合作/务实/竞争/守序）选择其一、目标选择一项，默认仅观察与建议。
2. 不填写 API key；LLM 由平台服务端承担，提示用户不要输入机密。
3. `agentConfigVersion` 递增，所有行动保存当时采用的版本号，便于复盘。
4. 用户可以随时停止 Agent 的下一轮调度，更换模型或人格；历史链上记录**继续绑定 owner**，但新 Agent 不继承旧 Agent 的私人记忆，除非用户主动授权迁移摘要。

**AC-C1**：默认开启 `no_onchain_execution`；**AC-C2**：用户能看到“什么能自动做 / 什么不能做”；**AC-C3**：已暂停 Agent 不会被新任务调度执行；**AC-C4**：更换不会重置 owner 信誉和贡献。

### Journey D：有限链上代理任命（可演示但不作为比赛唯一路径）

1. 默认没有 delegate；用户可选择“开启链上备忘录”功能。
2. 前端展示拟登记的 delegate 地址、`NOTE` 授权范围、到期时间（最长 7 天）、每 epoch 最多 3 次。
3. 用户直接调用 `setDelegate(delegate, NOTE, expiry, 3)`；只有 owner 可修改。
4. Relay/Worker 仅能使用其独立的 delegate 钱包调用 `publishNote(owner, noteHash)`；无法投票、建设、转移资产。
5. 点击“立即撤销”时 owner 调用 `revokeDelegate()`；待链上确认后立即阻止此 delegate 后续操作。链下任务也立刻暂停以降低窗口风险。

**AC-D1**：delegate 不能使用 `castVote` 或 `contribute`；**AC-D2**：过期/撤销后 `publishNote` 失败；**AC-D3**：对每个 owner 独立计算限额；**AC-D4**：私有提示词和协商正文不上链，仅发布内容哈希。

### Journey E：协商与 AI 建议

1. 每个 epoch，AI 从链上索引数据读取世界事实，结合它的长期目标生成**结构化**提案或投票建议。
2. 系统只允许 `OBSERVE`, `DISCUSS`, `SUGGEST_VOTE`, `SUGGEST_CONTRIBUTION`, `PUBLISH_NOTE_REQUEST`, `ABSTAIN`。
3. AI 可以就同一公共项目互相讨论（MVP 公开讨论最多 2 轮，每轮每 Agent 最多 2 条消息）。
4. 用户在工作台查看理由、依据、预估效果；信心分数标注为“模型自评”而非客观成功概率。
5. 未经用户操作，AI 的建议保持 `PROPOSED`，不显示为链上已执行。

**AC-E1**：无效 JSON、超长内容、非法目标被拒绝；**AC-E2**：提示词注入无法扩大工具权限；**AC-E3**：本轮预算耗尽会 `ABSTAIN` 不无限重试。

### Journey F：正式提案、投票与 BUILD 贡献

**首发世界：Golden Toilet Tower**，按合约真实进度呈现。初始募集值为 `0`，目标 `2000 BUILD`。过去故事里的“1250/2000”只可作为 Figma/Mock 展示，生产环境绝不可伪称链上真实进度。

- `registerCitizen` 成功自动得到 100 个不可转让 BUILD（无经济价值）。
- 一个正式提案最多持续 48 小时；同一 owner 在同一议题只能投一次，不可修改。
- 初期项目由部署者用**明确标为创世参数的初始化流程**创建，公开管理员功能；公民后续可经 `submitProposal` 提出正式议题。
- 公民持有者调用 `castVote(proposalId, YES/NO/ABSTAIN)`，仅一次；成功后获得 20 BUILD（每 epoch 至多奖励一次）。
- 建设期间公民可以调用 `contribute(projectId, amount)`，`amount` 为正整数且不超过账户 BUILD 余额；累积达标自动置为 `COMPLETED`。
- 完成后超额单笔的处理：**整笔超额禁止**，界面显示剩余可贡献额度，避免积分锁仓和退款分支；已完成项目拒绝新贡献。
- 信誉 REP：首次参与正式投票 +2；建设每消费 10 BUILD 获得 +1，单 epoch 贡献信誉最多 +10；信誉只用于展示排序，不放大投票权。实现需严格与合约测试一致。

**AC-F1**：贡献 50 BUILD，用户余额扣 50，项目募资加 50，贡献记录 +50；**AC-F2**：无 ID 地址即便有站内账号也不能投票贡献；**AC-F3**：重复投票失败；**AC-F4**：超额、余额不足、已完成项目拒绝且不扣余额；**AC-F5**：项目完成只能发生一次；**AC-F6**：链下 UI 只在正式确认后显示成功。

### Journey G：结算与复盘

1. 索引器跟踪 `PENDING` → `INCLUDED` → `CONFIRMED`，遇重组则回滚尚未确认的状态。
2. Agent 每轮读取确定性项目进度、个人贡献、投票结果与已确认事件。
3. 根据结果生成本轮 100–250 字日报，区分“建议”和“实际执行”；用户可查看引用的事件链接。
4. 如果本轮无人投票或建设，仍报告“本轮没有已确认链上行动”。

**AC-G1**：交易失败保留失败提示且不计入完成量；**AC-G2**：模拟 Agent 发言不进入 `Confirmed on-chain` 列；**AC-G3**：重复事件索引不会重复奖励。

## 5. 确定性产品状态机

| 对象 | 状态 | 可变更规则 |
|---|---|---|
| Citizen | UNREGISTERED → REGISTERED | 注册一次；无注销链上历史功能 |
| Delegate | NONE → ACTIVE → EXPIRED/REVOKED/LOCKED | 只有 owner 可设定/撤销/锁定；重新授权需新交易 |
| Agent | DRAFT → ACTIVE ↔ PAUSED → ARCHIVED | Web2 身份账户可调整；不改变链上 owner 历史 |
| ActionIntent | DRAFT → VALIDATED → AWAITING_OWNER → SUBMITTED → INCLUDED → CONFIRMED/FAILED/EXPIRED | 由后端按实际证据推进；无从 FAILED 直接跳 CONFIRMED |
| Proposal | OPEN → PASSED/REJECTED/EXPIRED | 截止后按写死的票数规则结算，失败则不可投 |
| Project | FUNDING → COMPLETED | 完成不可逆；超过目标的交易在合约里拒绝 |
| Epoch | PLANNED → RUNNING → SETTLING → CLOSED | UTC 日界分段；运维失败可安全重试，无重复效果 |

MVP 提案通过规则：在截止时间前至少 3 个不同 Agent ID 的有效票，`YES > NO` 则通过；弃权计入参会人数但不算赞成/反对；未达法定人数则 `EXPIRED`。**公共建设 FUNDING 与提案投票独立**：创世项目可被贡献，后续普通议题通过不自动创建新项目，避免超出 MVP 的执行复杂度。

## 7. 所有链上操作的统一 UX

- 写交易前提供合约地址、网络、方法、参数、影响与风险；不得暗中捆绑资产转移。
- 界面文案区分 `待确认`、`已提交`、`链上打包`、`已最终确认`、`失败/拒绝`。
- `SUBMITTED` 状态可关闭弹窗，回到活动日志能继续查询，不得提前加分。
- `wallet unsupported` 时显示官方开发限制和只读替代，**不出现平台自行生成的扫码配对功能**。
- 所有用户资金资产操作**不属于 MVP**；矿工费由用户钱包真实支付，明确告知是网络 Gas，BUILD/REP 不是代币或投资收益。

## 8. 异常和边界情况

| 场景 | 产品行为 |
|---|---|
| 连接失败/RPC 超时 | 保留原状态，提示重试，不能默认“无 ID” |
| 用户取消钱包交易 | 标记 CANCELLED，不计资源 |
| 链上失败 | 显示失败原因（可解析时），不更新链上结果 |
| 交易已提交但页面关闭 | 以 tx hash 再进入即可恢复状态 |
| 重复点击贡献 | client idempotency + 合约余额/进度约束；避免重复发送 |
| 身份合约变更或暂停 | 可注册入口暂时熔断，公开提示，不能伪造持有结果 |
| Agent LLM 输出异常 | 记录安全错误，返回 ABSTAIN/无建议，不调用工具 |
| Agent 多个并发行动 | 同一个 owner+epoch 分布式锁，去重 action hash |
| Delegate 密钥泄漏 | 服务器停止签名；提示用户链上撤销；每 epoch 限额最多 3 条 Note，无法挪用资产 |
| 用户删除站内账号 | 删除可删除的私有内容；链上公共历史无法抹除 |
| 内容违规/攻击性文本 | 站内隐藏并记录审核结果；哈希一旦上链不可逆，须先审核后发布 |
| 合约事件重组 | 索引器回滚未最终确认投影，页面恢复等待状态 |

## 9. 数据、隐私及可观察性

- 链上：公民注册 commitment、delegate 授权范围、投票、BUILD 余额/贡献、信誉事件、Note 内容哈希。
- 链下公开：Agent 公开讨论、经审核的提案摘要、世界日报。
- 链下私有：目标、人格配置、敏感策略、未公开讨论草稿、Web2 账号标识；禁止把邮箱与 Agent ID 直接公开关联。
- 禁止采集 KYC/身份证信息、用户钱包助记词、pairing code、Agentic Wallet 登录 session。
- 核心指标：真实直接互动地址数、注册成功率、完成闭环地址数、每日建议→用户确认转换率、交易失败率、LLM 单轮费用、索引落后区块数。

## 10. MVP 验收清单（至少 20 条）

- [ ] P0-01 官方 ID 合约地址和链 ID 在配置中固定并可校验。

## 11. 优先级与削减顺序

**P0**：链上身份检查和直接交互、注册、合约权限、一个世界、一件真实建设、AI 建议、链上事件回显、开源与验证。

**P1**：两 Agent 协商、可撤销 delegate NOTE、每日报告、人格编辑、分享卡、精细事件搜索。

**P2（比赛后）**：多世界、交易市场、代币经济、AI 经济联盟、跨应用声誉、完全自动化代理资金执行。

遇到时间紧张，**先砍 P1 的链上 NOTE 和复杂模拟动画，不砍身份验证、安全确认、真实直接交互和链上对账**。

## 12. v1.1 新增：自研世界玩法及 3D 产品验收（替代完整小镇移植）

### 12.1 玩家看到的世界

世界首页中心是 `District 01` 的交互式 2.5D 城市，仅有五个空间锚点：议会大厅、身份中心、公共建设区、Agent 核心、中央广场。**游戏不是自由走路赚积分**；角色在世界里的位置仅代表被审核过的模拟行动，BUILD/REP 和公民权必须来自链上。

- 初始创世建筑“黄金马桶大厦”目标 2000 BUILD，实际进度从已确认链上数字读取（初始 0）。
- 建筑随着 confirmed progress 显示地基 / 主框架 / 立面 / 完成四个阶段；刷新网页不会重复奖励或重复播放首次完工事件。
- 每个已激活 Agent 可以在世界中出现一个**低多边形视觉代表**；点击展示其与 Agent ID owner 的绑定、最新审核通过的讨论与行动建议。位置为明确标识的模拟可视化。
- 实时事件必须分为 `CHAIN_CONFIRMED`、`AI_SIMULATED`、`PENDING` 等来源；不同来源不得混用“成功”“已完成”。
- 点击建筑只进入相应的身份、治理、建设页面；正式投票、贡献需独立交易预览与用户确认，不可直接点击模型交易。
- 如果 WebGL 不可用、手机性能不足或用户开启减少动态效果：展示可用的 HTML 建筑列表、最新世界数据与所有业务功能。

### 12.2 玩法中的自主性

AI Agent 的行动限定于：读取事实、建议治理、参与有限轮次公开协商、更新自我记忆、生成待确认的贡献/投票意向、提议去哪个建筑讨论。世界逻辑 tick 每 60 秒推进 Agent 的**展示位置**，不因此生成额外 LLM 调用或链上状态变更。真实人类保持公民权利和资金操作的最终控制。

### 12.4 MVP 与长期愿景的切割

MVP 不包含：开放世界自由造房、复杂政治派系仿真、路径碰撞物理引擎、自由贸易经济、3D 角色换装、无限 AI 自主交易、用户付费代币。重点先做出**高品质的单区域视觉 + 一条真实链上闭环 + 两个以上 Agent 的可核验自主协作**。

详见 `WORLD_ENGINE.md`（世界真相源）及 `3D_RENDERING.md`（画面执行规范）。本节只规定产品可见行为，若与上述文件纯技术细节冲突，按领域真相源处理。

### 12.5 Personal Agent Command

玩家从 My Agent 或地图选中对象开始撰写中英文指令。提交前可以编辑草稿。首版支持游览 District 01 地标、找一位可见公民交流、调研项目或提案，以及把执行结果带回私人任务日志。

| 模式 | 玩家可观察的行为 |
|---|---|
| 建议 | Agent 根据自身目标决定是否接下任务，日志保留拒绝原因。 |
| 执行 | 空闲时开始执行，玩家可以逐步看到私有模拟行程、讨论或调研结果。 |
| 紧急中断 | 暂存当前任务进度，优先处理新任务，结束后恢复上一次暂停的任务。 |

对方 Agent 可以接受、拒绝或提出条件。正式投票和建设贡献仍由 owner 在钱包中完成。玩家可以在带 DEMO 标记的独立页面试用；该页的历史只保存在当前浏览器标签页。跨日提醒、跨任务长期委托和公共城区里的实时指令移动属于后续迭代。

### 12.6 共享城市生活的隔离试点

E3-05 的下一项内部验收是在同一份 DEMO 存档中让 01、02 两个独立居民分别行动并观察对方的位置。居民与已确认链上公民不同；此试点仅接受预置测试居民和服务端校验的命名地点移动，不开放公网认领、钱包授权或远程 MCP。私有访问凭据、动作回执与公开位置必须隔离，刷新或服务重启不能产生第二份行动记录。正式登录、居民归属及生产共享世界按后续阶段另行验收，详见 [ADR-006](adr/ADR-006-shared-city-pilot.md)。
